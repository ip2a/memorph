# 项目骨架设计 v1

> **配套文档**:《架构文档-重要架构设计v1.md》(分层分发模型、铁律、命名规则)。
> 本文给出**完整版**的项目目录结构、脚本设计与发布流水线。
>
> **完整版包含全部四条交付链**:Rust 核心 lib(`cargo add`)、CLI(npm / curl)、Python 绑定(pip)、桌面发行版(GitHub Releases)。
> 项目可**按需裁剪**(见 §11)。本文以 `myapp` 作为示例项目名占位,实际替换为你自己的项目名。

## 2. rust/ workspace 四个 crate

| crate | 路径 | 类型 | publish | 依赖 | 产物 |
|---|---|---|---|---|---|
| `myapp` | `rust/crates/myapp` | lib | ✅ crates.io | 无应用层依赖 | 核心 lib |
| `myapp-cli` | `rust/apps/myapp-cli` | bin | ❌ false | `myapp` + clap/ratatui/axum | 二进制 `myapp` |
| `myapp-python` | `rust/bindings/python` | cdylib | ❌ false | `myapp` + pyo3 | `_rust.{so,pyd,dylib}` |
| `myapp-tauri` | `desktop/tauri` | bin+lib | ❌ false | `myapp-cli` + tauri | `.app/.dmg/.msi` |

### 版本源头

`rust/Cargo.toml` 的 `[workspace.package] version` 是**唯一版本源头**。各 crate 用 `version.workspace = true` 继承。`scripts/sync_version.py` 负责把这个版本号传播到所有非 Rust 的 manifest(见 §7)。

### 核心 lib 的边界(继承架构文档 §9)

- `myapp`(核心 lib)= **领域逻辑 + 数据/文件 IO**。
- **不包含**:CLI 参数解析、TUI 渲染、HTTP server、桌面 GUI、MCP server —— 这些全归 `myapp-cli`。
- 重依赖(axum / ratatui / crossterm / clap 等)一律在 `myapp-cli`;核心 lib 必须留下的重依赖用 Cargo feature 门控。

## 3. 分发层目录

| 目录 | 内容 | 打包工具 |
|---|---|---|
| `npm/packages/myapp/` | 主包 shim,安装时按平台选 `myapp-bin-<triple>` 子包 | `npm publish` |
| `npm/packages/myapp-bin-<triple>/` | 各 Rust target triple 一个,内含预编译二进制 | `npm publish` |
| `python/packages/myapp/` | `pyproject.toml` + Python wrapper + 各平台 cdylib | `maturin` + `twine` |
| `desktop/tauri/` | Tauri 配置 + 桌面壳代码 | `tauri build` |

> npm 子包按 **Rust target triple** 划分(如 `myapp-bin-x86_64-apple-darwin`)。也可改为 `optionalDependencies` 一包搞定(参考 esbuild),由项目自定。

## 4. scripts/ 脚本清单

| 脚本 | 何时跑 | 职责 |
|---|---|---|
| `sync_version.py` | 改版本后 / CI 发版前 | 从 workspace 根读 version,写回所有平台 manifest |
| `build_web_assets.sh` | 打包 CLI 前 | `npm run build` → 拷 `web/dist` 到 `myapp-cli/assets/web` |
| `build_target.sh` | release-build workflow | `cargo build --release --target <triple>` → 拷到 `dist/<platform-id>/` |
| `assemble_npm_packages.py` | 发 npm 前 | 把 `dist/` 二进制装进各 `myapp-bin-<triple>` 子包 |
| `assemble_pypi_packages.py` | 发 pypi 前 | 用 maturin 把 cdylib + wrapper 打成各平台 wheel |
| `assemble_desktop.py` | 发桌面发行版前 | `tauri build` → 收集 `.dmg/.msi/.AppImage` |
| `install.sh` | 用户 `curl \| sh` | 平台/arch 检测 → 下载对应预编译二进制 → 装 PATH |
| `release_preflight.py` | 发版前(CI gate) | 版本一致性、产物存在、`publish` 标记正确 |
| `release_readiness.py` | 发版前 | 综合就绪检查 |

## 5. 本地开发脚本

### 5.1 run_debug.sh(开发菜单)

按场景串起各部件的 dev 流程,避免手敲一串命令。

```bash
#!/usr/bin/env bash
set -euo pipefail

PS3="选择开发模式 > "
select mode in "web (Vite HMR + api backend)" \
               "desktop (Tauri dev)" \
               "tui" \
               "python 绑定" \
               "clean" \
               "退出"; do
  case "$REPLY" in
    1) # 前端 HMR:Vite 指向一个跑着的 api 后端
       # MYAPP_API_TARGET 由前端 dev server 读取,反代到 api
       MYAPP_API_TARGET=http://127.0.0.1:3737 npm --prefix web run dev &
       cargo run --manifest-path rust/apps/myapp-cli/Cargo.toml --bin myapp -- api --port 3737
       ;;
    2) cargo run --manifest-path desktop/tauri/Cargo.toml ;;
    3) cargo run --manifest-path rust/apps/myapp-cli/Cargo.toml --bin myapp -- tui ;;
    4) # PyO3 绑定:maturin develop 即时装进当前 venv
       maturin develop --manifest-path rust/bindings/python/Cargo.toml ;;
    5) cargo clean --manifest-path rust/Cargo.toml
       rm -rf web/dist web/node_modules dist ;;
    6) exit 0 ;;
  esac
done
```

### 5.2 init.sh(一次性 preflight)

提交前 / CI 入口的快速校验。

```bash
#!/usr/bin/env bash
set -euo pipefail
npm --prefix web ci
npm --prefix web run lint
npm --prefix web run build
python3 scripts/release_preflight.py
cargo check --locked --manifest-path rust/Cargo.toml
```

## 6. curl | sh 安装脚本(install.sh)

这是**最完善**渠道(L3),给非 npm / 非 cargo 用户的零依赖一键安装。

```bash
#!/usr/bin/env sh
# 用法:curl -fsSL https://myapp.dev/install.sh | sh
set -eu

# 1. 平台 + 架构检测 → 拼 platform-id
OS=$(uname -s)            # Darwin / Linux
ARCH=$(uname -m)          # arm64 / x86_64 / ...
case "$OS/$ARCH" in
  Darwin/arm64)  PLATFORM_ID="darwin-arm64" ;;
  Darwin/x86_64) PLATFORM_ID="darwin-x64" ;;
  Linux/x86_64)  PLATFORM_ID="linux-x64" ;;
  Linux/aarch64) PLATFORM_ID="linux-arm64" ;;
  *) echo "不支持的平台: $OS/$ARCH"; exit 1 ;;
esac

# 2. 取最新版本号(由发版流程产出的 latest manifest)
VERSION=$(curl -fsSL "https://github.com/<org>/myapp/releases/latest/download/latest-release-manifest.json" \
          | grep -o '"version":"[^"]*"' | head -1 | cut -d'"' -f4)

# 3. 下载对应预编译二进制并解压
URL="https://github.com/<org>/myapp/releases/download/v${VERSION}/myapp-${PLATFORM_ID}.tar.gz"
curl -fsSL "$URL" | tar xz -C /tmp

# 4. 安装到 PATH(优先 ~/.local/bin)
INSTALL_DIR="${HOME}/.local/bin"
mkdir -p "$INSTALL_DIR"
mv /tmp/myapp "$INSTALL_DIR/myapp"
echo "已安装到 $INSTALL_DIR/myapp,请确认该目录在你的 PATH 中"
```

> 生产级还需补:**checksum 校验**(对照 release 同发的 `.sha256`)、**签名验证**、**已存在版本的升级/卸载提示**。骨架只示意思路。

## 7. 版本锁步(sync_version.py)

**唯一源头**:`rust/Cargo.toml` 的 `[workspace.package] version`。

**传播目标**:

| 目标文件 | 字段 |
|---|---|
| `web/package.json` | `version` |
| `npm/packages/myapp/package.json` | `version` |
| `npm/packages/myapp-bin-<triple>/package.json` | `version`(各子包) |
| `python/packages/myapp/pyproject.toml` | `version` |
| `desktop/tauri/tauri.conf.json` | `version` |
| `desktop/tauri/Cargo.toml` | `version`(若不继承 workspace) |

骨架:

```python
# scripts/sync_version.py
import tomllib, json, re
from pathlib import Path

ROOT = Path(__file__).resolve().parent.parent

def read_workspace_version() -> str:
    cargo = tomllib.loads((ROOT / "rust/Cargo.toml").read_text(encoding="utf-8"))
    return cargo["package"]["version"]  # [workspace.package] 在 [package] 段下

def write_json(path: Path, version: str):
    data = json.loads(path.read_text(encoding="utf-8"))
    data["version"] = version
    path.write_text(json.dumps(data, indent=2, ensure_ascii=False) + "\n", encoding="utf-8")

# ... 各目标的写入逻辑
```

## 8. 构建与打包脚本

| 脚本 | 关键设计 |
|---|---|
| `build_web_assets.sh` | 先跑 `build_target.sh` 前调用;`cd web && npm run build` → `cp -r dist ../rust/apps/myapp-cli/assets/web`。**发布构建前必须跑,否则内嵌 SPA 是旧的。** |
| `build_target.sh <triple> <platform-id> <artifact>` | 调 `build_web_assets.sh` → `cargo build --release --target <triple>` → `cp` artifact 到 `dist/<platform-id>/` |
| `assemble_npm_packages.py` | 遍历 `dist/<platform-id>/`,把二进制塞进对应 `myapp-bin-<triple>/bin/` |
| `assemble_pypi_packages.py` | 用 `maturin build --target <triple> --release` 产 wheel,收集到 `python/packages/myapp/dist/` |
| `assemble_desktop.py` | 跑 `tauri build`,收集 `desktop/tauri/target/release/bundle/` 下的 `.dmg/.msi/.AppImage` |

## 9. GitHub Actions

### 9.1 workflow 清单

| workflow | 触发 | 职责 |
|---|---|---|
| `ci.yml` | push / PR | web lint+build、`cargo check --locked`、`cargo test`、`release_preflight.py`、invariants |
| `release-build-linux.yml` | tag `v*` | matrix 编译 Linux(x64 / arm64)→ `build_target.sh` → 上传 artifact |
| `release-build-macos.yml` | tag `v*` | 编译 macOS(x64 / arm64) |
| `release-build-windows.yml` | tag `v*` | 编译 Windows |
| `release-publish-crates.yml` | build 完后 | `cargo publish` 核心 lib 到 crates.io |
| `release-publish-npm.yml` | build 完后 | `assemble_npm_packages.py` → `npm publish` 主包 + 各 `myapp-bin-<triple>` |
| `release-publish-pypi.yml` | build 完后 | `assemble_pypi_packages.py` → `twine upload` |
| `release-publish-desktop.yml` | build 完后 | `assemble_desktop.py` → 上传 GitHub Releases |
| `post-release-verify.yml` | publish 后 | 轮询各平台确认版本可见(crates.io / npm / pypi / releases) |

### 9.2 发版流程(端到端)

```
改 rust/Cargo.toml 的 version
  → sync_version.py 传播到所有 manifest
    → commit + tag v<x.y.z> + push
      → release-build-{linux,macos,windows} (matrix 编译,产出 dist/)
        → release-publish-{crates,npm,pypi,desktop} (并行发布)
          → post-release-verify (验证全平台可见)
```

**关键约束**:
- `release-build-*` 必须先跑 `build_web_assets.sh`,确保 CLI 内嵌的 SPA 是最新的。
- `release-publish-crates.yml` 只发布核心 lib,且发布前用 `cargo publish --dry-run` 校验(核心 lib 不允许有未发布的 path 依赖)。
- `post-release-verify.yml` 轮询各平台 API,确认 `<version>` 可见后才算发版成功。

## 11. 按需裁剪指引

完整版包含全部四条交付链。**项目按目标用户群裁剪**,砍掉对应目录 / 脚本 / workflow 即可,核心 lib 与 CLI 两条主链保留。

| 不要哪条链 | 砍掉这些 | 同时影响 |
|---|---|---|
| **Web 前端** | `web/`、`scripts/build_web_assets.sh`、`myapp-cli/build.rs` 的内嵌逻辑、`myapp-cli/assets/web`、`myapp-cli/src/{web.rs,api/}`(若 api 仅服务 SPA) | `run_debug.sh` 去掉模式 1;`init.sh` 去掉 web lint/build;`ci.yml` 去掉 web 校验 |
| **桌面发行版** | `desktop/`、`scripts/assemble_desktop.py`、`release-publish-desktop.yml` | 架构文档 L3「完全体发行版」一行取消;`run_debug.sh` 去掉模式 2 |
| **Python 绑定** | `rust/bindings/python/`、`python/`、`scripts/assemble_pypi_packages.py`、`release-publish-pypi.yml` | 架构文档 L1「pip 绑定」与 §7「uvx 三选一」取消;`run_debug.sh` 去掉模式 4 |
| **npm 渠道** | `npm/`、`scripts/assemble_npm_packages.py`、`release-publish-npm.yml` | L2「npx」与 L3「npm i -g」取消;CLI 只走 `curl \| sh` |

> **铁律不变**:无论怎么裁,用户可见名仍是 `myapp`,核心 lib 仍是唯一发 crates.io 的 crate,CLI 内嵌的交互形态(TUI / api / mcp)归 `myapp-cli`。
