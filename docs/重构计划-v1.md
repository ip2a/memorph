# memorph 架构重构计划 v1

> **本文是验收标准。** 配套《架构文档-重要架构设计v1.md》《项目骨架设计v1.md》。
> 目标:把 memorph 从"单 crate(lib+bin 合一)"重构为规范的 workspace(核心 lib + CLI + 桌面壳),符合《架构文档 v1》的分层模型。
>
> **执行原则**:渐进迁移,每个里程碑独立 commit + 验证;**不留 Helper / Adapter / 兼容 re-export / shim / 回退补丁**;业务行为零回归。

## 2. 现状(调研结论)

- 单 crate `memorph`,lib + bin 合一,**src 约 11.2 万行**
- workspace 根已存在:`rust/Cargo.toml`,`members = ["crates/*"]`
- 应用层依赖集中在:`api/`、`server.rs`、`tui/`、`web.rs`、`web_assets.rs`、`cli.rs`、`bin/`、`hooks/server.rs`、`skills/server.rs`
- **核心生产代码干净**;唯一核心层对应用 router 的引用是 `providers/gemini/mod.rs` 的一个 `#[cfg(test)]`(通过 `crate::api::router().oneshot()` 做 API 端到端测试)→ M3 归位
- 外部 `memorph::` 消费者只有 **2 处**:`rust/crates/memorph/tests/compression_cli.rs`、`desktop/tauri/src/lib.rs`
- `build.rs` 内嵌 `apps/web/dist`(优先)或 `assets/web`(回退);`web_assets.rs` 全 axum

## 3. 目标架构

```
rust/
├── Cargo.toml                 # workspace: members = ["crates/*", "apps/*"]
├── crates/memorph/            # ★ 核心 lib(发 crates.io)
│   ├── Cargo.toml             # 无 axum/ratatui/clap/crossterm/tower_http/open
│   ├── assets/i18n.json       # 核心数据
│   └── src/                   # 领域逻辑 + IO
└── apps/memorph-cli/          # CLI(publish = false)
    ├── Cargo.toml             # 依赖 memorph + axum/ratatui/clap/...
    ├── build.rs               # 内嵌 web assets
    ├── assets/web/            # web dist 回退位置
    └── src/
        ├── lib.rs             # pub mod 应用模块
        ├── bin/               # memorph.rs, memo.rs
        ├── cli.rs, server.rs, api/, web.rs, web_assets.rs, tui/
        └── (hooks server / skills server 归位处)

desktop/tauri/                 # 壳(保持独立,不进 rust workspace)
└── 依赖 memorph-cli(path)
```

## 6. use 路径调整规则(关键)

模块移动后,引用路径按以下规则调整:

- **核心 crate 内部**:`crate::xxx` **不变**(都在核心)
- **CLI 应用模块互引用**:`crate::api`、`crate::server` **不变**(同在 CLI lib)
- **CLI 引用核心模块**:`crate::core` → `memorph::core`,`crate::canonical` → `memorph::canonical`,以此类推

核心模块集合(CLI 里 `crate::X` → `memorph::X`):
> `canonical`、`provider`、`providers`、`core`、`storage`、`format`、`cache`、`sync`、`session_projection`、`stats_dashboard`、`agent_environment`、`agent_management`、`provider_settings`、`config`、`logging`、`i18n`、`utils`、`hooks`(非 server)、`skills`(非 server)

CLI crate 名为 `memorph-cli`,lib 名默认 `memorph_cli`;bin 通过 `use memorph_cli::{...}` + `use memorph::{...}` 访问。

### M2 — 应用层迁移(先解耦,再移动)

**调研发现(导致 M2 细化)**:`hooks/server.rs`(1318 行)与 `skills/server.rs`(1893 行)是**核心逻辑 + axum handler 的混合体**,被核心模块深度依赖 —— `hooks::server` 的运行时快照/endpoint 被 `agent_management`/`session_management`/`projection`/`augmentation`/`diagnostics` 调用;`skills::server` 的类型(`SkillInstallation`/`SkillStatistics`)被 `scanner` 调用;且 `hooks/server` 的 handler 反向调 `api::run_blocking`(本质 `spawn_blocking` 工具)。整体移动会导致核心断裂,且 `hooks/server`→`api` 形成 core→app 反向依赖。

故 M2 细化为"**先在核心内部解耦(提取核心层),再整体迁移应用层**",每步独立 commit、可独立验证:

#### M2a — 提取 `run_blocking` 到核心
- 动作:`api::run_blocking`(`spawn_blocking` 包装)提取到核心新模块 `runtime.rs` 并 `pub`;14 处调用点(`hooks/server.rs`)改 `crate::runtime::run_blocking`
- 验证:`cargo check` + `cargo test`
- commit:`refactor(core): 提取 run_blocking 工具到核心 runtime 模块`

#### M2b — 拆分 `hooks/server.rs`(核心运行时 vs axum)
- 动作:运行时函数(`publish_runtime_endpoint`/`current_runtime_endpoint`、`runtime_sessions_snapshot`、`linked_runtime_sessions*`、`cleanup_runtime_state` + `RUNTIME_STATE`/`RUNTIME_ENDPOINT` static + 支持函数)提取到核心 `hooks/runtime_state.rs`;`hooks/server.rs` 只剩 axum handler,引用 `crate::hooks::runtime_state::`;核心 5 处调用点改 `hooks::runtime_state::`
- 验证:`cargo check` + `cargo test`
- commit:`refactor(hooks): 拆出运行时状态层到 runtime_state`

#### M2c — 拆分 `skills/server.rs`(类型 vs axum)
- 动作:`SkillInstallation`/`SkillStatistics`/`SkillAsset`/`SkillIssue`/`SkillEntry` 等类型提取到核心 `skills/model.rs`;`skills/server.rs` 引用 `crate::skills::model::`;`scanner` 调用点改
- 验证:`cargo check` + `cargo test`
- commit:`refactor(skills): 拆出类型层到 model`

#### M2d — 整体迁移应用簇到 CLI
- 动作:`web`/`web_assets`/`build.rs`/`tui`/`api`/`server.rs`/`cli`/`bin`/`hooks::server`(纯 axum)/`skills::server`(纯 axum)→ CLI;`use` 路径调整(`crate::核心` → `memorph::核心`,`bin` 的 `memorph::应用` → `memorph_cli::应用`);核心 `lib.rs`/`hooks/mod`/`skills/mod` 删对应声明;gemini 的 api 集成测试改写为直接调核心函数
- 验证:`cargo check` + `cargo test`
- commit:`refactor: 应用层整体迁入 memorph-cli`

#### M2e — 核心清理应用依赖
- 动作:核心 `Cargo.toml` 删 `axum`/`tower-http`/`clap`/`ratatui`/`crossterm`/`open`;`[dev-dependencies]` 清理
